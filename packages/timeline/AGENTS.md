# Timeline (`packages/timeline/`)

The Overview tab's Timeline panel: one line per thing that happened inside Sovereign, newest first, live. A package of its own, like the scheduler and notifications: it owns a data dir, a route and a WS channel, and it reads events from many packages through the bus alone, so it imports none of them. The record type (`TimelineEntry`, `TurnOrigin`, `TIMELINE_KINDS`) lives in `@sovereign/core` (`timeline.ts`, also exported as `@sovereign/core/timeline` for the client).

- **Mapping** (`mapping.ts`, pure). Only the event types below map to anything (`TIMELINE_EVENT_TYPES`). Everything else gives nothing: `chat.stream`, `chat.work`, tool calls, `chat.status`, `chat.turn(.completed)`, `forge.updated`/`forge.overlay`, metrics. Titles and details are one line, clipped to 200 characters. A malformed payload maps to nothing. **The emit site supplies what a line needs** (a turn's origin, a sync's admitted count, a run's trigger). Never reconstruct it in the mapping.
- **Forge lines come only from `forge.events`**, which the work graph emits in `logEvents` (service.ts) next to the event log append. That covers a membrane sync, tracked items and plan edits, all after the `forge.trustedAuthors` filter and triage. Comment text is dropped (`forgeEventLine` in events.ts). An untrusted author's item therefore never reaches the timeline (`work-graph/src/timeline.test.ts`).

- **Turn origin** (`TurnOrigin`: user, cron, rethink, agent, subagent, system). `SendOptions.via` sets it at each `handleSend`. Without it, `viaOf` decides: an `origin` with modality cron → cron, ad4m/webhook → system, any other modality → user; no origin with `synthRole: 'system'` → system; else user. Bootstrap tags rethink sends (`rethink`), `task_send_prompt` and presence forwarding (`agent`), cron fires (`cron`), subagent results (`subagent`: `deliverToParent` injects with `kind: 'subagent'`) and the voice-error report (`system`). `sessions_send` bypasses the queue, so `mcp-deps.ts` emits `chat.message.injected { sessionKey, via: 'agent' }` first; the chat module holds it until that session goes busy. A turn nobody queued (a resume) is system. A turn opens when its queued message is dispatched, or at the first non-idle status, whichever comes first. The backend can report busy before `sendMessage` resolves, so the dispatch's origin is staged in `dispatching`. The turn closes at that spell's idle: the backend's, the one chat synthesizes after an assistant turn, or the stuck watchdog's. Only threads count. A subagent's session has its own `subagent.*` lines. `chat.message.sent` carries `via` too.
- **Storage** (`store.ts`): `<dataDir>/timeline/YYYY-MM-DD.jsonl` (UTC day of the entry), append-only, plus an in-memory ring of the newest 2000. Ids are `t<epoch ms base 36>-<random>`, and times are strictly increasing (a late or same-millisecond entry moves 1 ms past the last), so an id is also a time cursor. A query the ring can answer never reads the disk. An older page reads day files newest first, below what the ring covers. A restart loads the newest files back into the ring. Day files older than 30 days are deleted at start and once a day. Broken lines are skipped.
- **API:** `GET /api/timeline?since=&until=&kinds=&origins=&limit=&before=` → `{ entries, more, next? }`, newest first. `since` is inclusive and `until` exclusive, both ISO. `kinds` and `origins` are comma lists of `TIMELINE_KINDS` / `TURN_ORIGINS`. `limit` runs 1–1000, default 200. `before` takes the previous page's `next`. Any bad or repeated parameter answers 400 with the reason.
- **WS:** channel `timeline`, server message `timeline.entry { entry }` for every new line.
- **Client** (`features/timeline/`): `TimelinePanel.tsx` is the middle column of the Overview (`DashboardView.tsx`), and `timeline-model.ts` holds its logic. A line shows the relative time (absolute on hover), a kind icon and colour (failures in `--c-error`), the title and a muted detail. A click opens the line's thread (workspace view), else its http(s) url in a new tab. Chips per kind and per origin (User / Automated = cron, rethink, agent, system / Subagent) are saved in localStorage (`sovereign:timeline:filters`), never on the server; the last chip on stays on. They narrow the server query, and live entries are filtered the same way. Lines are grouped by local day (Today, Yesterday, then the date). "Load older" pages back with `before`. A live line goes on top. While the list is scrolled, the scroll shifts by the added height, so the line being read stays put.
